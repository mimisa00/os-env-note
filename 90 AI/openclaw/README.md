# 筆記

1. 自動化開發非常燒 Token，若沒有進行優化的話，一則較複雜的 Issue 處理可能就會花到10美金上下，故需想辦法透過各種方式節省 token 輸出，尤其是採用封閉型 LLM API 時，如果有快取可以使用，則應朝該方向進行設計或啟用相關功能，以節省相差 10 倍以上的成本支出，另外優化 Prompt 及將任務進行有效分割也能將主 Context 的內容使用的 token 縮小不少
2. openclaw 跟 claudecode 的長處各不相同，若系統較舊的情況下，透過 openclaw 打造全自動化開發產線會相對簡易很多(openclaw 擅長爬虫網頁介面及點擊各種需要人工點擊的按鍵)，可能舊系統大多都不支援 API 引用，導致 Claude Code 這種以 MCP 為基礎協議架構的溝通模式，將會非常困難運作，但是相對的，如果系統夠新，則透過 API 溝通，則相對節省 token 支出
3. 很多機械化操作，盡量用現成的工具或透過客制腳本完成，這樣也可以節省不少 token 支出
